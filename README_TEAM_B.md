# Project B – AV Trajectory Planner (Teams 7–12)

**Team members:** Anthony Pollard, Cole Pulaski, Will Cunningham, Brandon Debrosse

## Overview
This is the **Group B** solution for the Autonomous Driving Challenge.
Our planner controls an ego vehicle, trying to pass as many scenes
(generated by Group A) as possible without crashing, while following US
traffic law. We also wrote a combined scene (`city_mix`) and a set of
stress-test scenes to check the planner on situations the example scenes
don't cover.

## How to Run

### 1. Install requirements (once)
```bash
python -m venv venv
venv\Scripts\activate            # macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
```

### 2. Watch a run
```bash
python run_simulation.py --list                                        # list scenes and planners
python run_simulation.py --scenario city_mix --planner student
python run_simulation.py --scenario st_cyclist_on_curve --planner student --debug
```

### 3. Score the planners
```bash
python evaluate.py --planner baseline student          # every scene, side by side
python tests/test_challenge.py                         # simulator self-test (19/19)
```

## Our Planner (`planners/student_planner.py`)

### Strategy
The planner uses **multi-candidate trajectory selection**, 20 times a second:

1. **Build candidates** – trajectories for:
   - Keep current lane (cruise / follow the vehicle ahead)
   - Change to the left or right lane (if the lane marking allows it and we are not near a junction)
   - Stop at a red/yellow light, stop sign (full stop, wait 2 s) or yield line
   - Yield to pedestrians at crosswalks
   - Stop before a predicted conflict

2. **Validate** – each candidate is checked for collisions against predicted
   road users over 8 s. Candidates that collide are rejected.

3. **Score** – valid candidates are ranked by cost:
   - Progress lost (main factor)
   - Lane change (+0.05), leaving the route lane (+0.10), abandoning a lane change midway (+0.40)
   - Harsh braking (+0.05 × |a| / 3 m/s²)
   - Pedestrian near a crosswalk (+0.20)

4. **Select best** – the cheapest valid candidate is executed.

5. **Emergency fallback** – if nothing is safe, retry with firmer braking
   (up to 6 m/s²), and if still nothing, brake to a full stop.

### Our improvements over the starting planner
| Change | Why |
|---|---|
| **Cruise at 97 % of the posted speed limit** (never above it) | Recovers time lost at stops without speeding |
| **Faster response**: max acceleration 2.0 m/s² (the simulator's controller limit), jerk limit 6 m/s³, following gap 1.2 s | Pulls away and reacts to changes sooner |
| **Plan for the slowest vehicle ahead, not just the nearest** | A car ahead of us will itself have to slow for a slow truck in front of it; we now start slowing early instead of braking hard later |
| **Lane-following prediction** of vehicles in our lanes | Predicting other cars in a straight line made cars in the next lane look like they cut into ours on curves, causing false emergency stops |
| **Score lane changes on the speed of the target lane** | The car still keeps its distance from the vehicle it is leaving, but now recognises that overtaking a cyclist or slow truck is faster, so it actually overtakes when the lane is clear |
| **Direction-aware crosswalk yielding** | Still stops for pedestrians in our path, walking toward it, or waiting at the kerb; moves off once the pedestrian has crossed our lane and is walking away |

### Requirements Met
| Requirement | How |
|---|---|
| Bounded acceleration | `max_accel = 2.0 m/s²`, `max_decel = 3.0 m/s²` (6.0 in emergencies), jerk ≤ 6 m/s³ |
| Bounded steering | Quintic lateral profile limits lateral acceleration to ≤ 1.8 m/s² |
| Bounded speed | Never above the posted speed limit (cruise at 97 % of it) |
| Don't crash | Collision prediction over 8 s (lane-following for vehicles, straight-line + 1.5 s time buffer for pedestrians and crossing traffic) |
| Navigate to destination | Route-lane preference in the cost function; returns to the route lane after overtaking |
| Follow US traffic law | Stops for red/yellow lights, full stop at stop signs, yields at uncontrolled junctions and to pedestrians |

## Our Scenes (`scenarios/`)

### `city_mix` (`student_scenario.py`)
Three events in a row on one 400 m street:
1. A delivery truck ahead brakes to a stop; the left lane is busy, so we must stop behind it.
2. The truck drives on through the crosswalk; then a waiting pedestrian crosses in front of us.
3. The truck slows to 4 m/s; we must wait for a gap in the left lane, overtake, and return before the goal.

One truck plays all three parts, so scripted road users never drive into each other.

### Stress tests (`stress_tests.py`, names start with `st_`)
| Scene | What it tests |
|---|---|
| `st_stop_sign_left_turn` | All-way stop, left turn across an oncoming car, car arriving from the right |
| `st_red_then_green` | Arrive at a red light, wait while cross traffic uses its green, go on green |
| `st_yellow_dilemma` | Light turns yellow ~25 m before the line at speed, red 3 s later |
| `st_right_turn_cross_car` | Right turn at an uncontrolled junction with a car approaching from the left |
| `st_cyclist_on_curve` | Cyclist at the lane edge on an S-curve with a busy left lane |
| `st_occluded_pedestrian` | Pedestrian steps out from in front of a parked truck (late detection) |
| `st_cut_in` | A car cuts in close in front, then brakes |
| `st_tight_gaps` | Platoon of crossing cars at an uncontrolled junction with one usable gap |
