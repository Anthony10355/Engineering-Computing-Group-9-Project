# Learned Example Planner (`learned_example`)

A small **neural-network planner trained by imitation learning**, included as a complete, working example of the train → weights → run pipeline. It is deliberately simple: it is **safe but slower than the baseline**, so it is a starting point, not a target. How to build your own is explained in [LEARNING_GUIDE.md](../../LEARNING_GUIDE.md).

## 1. Run it

It needs PyTorch (CPU is enough). Without PyTorch the rest of the project works as usual and this planner is simply not listed.

```bash
pip install torch                         # once (or: pip install -r planners/learned_example/requirements.txt)

python run_simulation.py --scenario lane_change_overtake --planner learned_example
python run_simulation.py --scenario intersection_crossing_traffic --planner learned_example --debug
python evaluate.py --planner baseline learned_example      # score table, side by side with the baseline
```

On screen the behaviour label is `LEARNED` when the network's plan is driven and `SAFETY_BRAKE` when the safety filter (section 4) took over.

## 3. The model

**Network:** fully connected, `141 → 256 → ReLU → 256 → ReLU → 16`, 106,256 parameters (PyTorch).

**Inputs: 141 numbers**, all computed from `obs` (ego frame, roughly scaled to −1…1). The planner never reads `obs.desired_speed_mps`: a real car does not know a "desired" speed, but it knows the posted limit (`obs.speed_limit_mps`), so that is what the network gets.

| Group | Count | Content |
|---|---|---|
| Ego | 6 | speed, acceleration, **posted speed limit**, distance to goal (capped at 100 m), sideways offset from the lane centre, lane heading at the car |
| Lane shape | 12 | x and y of the current lane centre at 0, 10, 20, 30, 40, 50 m ahead |
| Neighbour lanes | 4 | left / right lane: exists, lane change allowed |
| Next stop line | 7 | distance; type (yield / stop sign / signal); light (red / yellow / green) |
| 8 nearest road users | 8 × 14 | present flag, x, y, distance along the lane, offset from the lane, vx, vy, heading (cos, sin), length, type (car / truck / bicycle / pedestrian); empty slots are zeros |

**Outputs: 16 numbers**, for the times 0.5, 1.0, …, 4.0 s:

* 8 × the car's **sideways offset from the current lane centre** (`d`, + = right; ±3.5 m means "in the neighbouring lane");
* 8 × the car's **speed**.

**From outputs to a trajectory** (`model.trajectory_from_output`):

1. The predicted speeds are clipped to 0 … speed limit, and the distance driven along the lane is their integral.
2. The offsets are clipped to lanes that exist and may be entered (no planning off the road or across a solid line).
3. Everything is interpolated to a 0.1 s grid and placed along the current lane with `planner_tools.build_trajectory`.

## 4. Safety filter (`planner.py`)

The network's plan is replaced by braking in the lane if:

* the output is implausible (not finite, offset beyond 6 m, speed far above the speed limit): a situation the network never saw; or
* the plan, continued to 6 s, would hit a road user ahead (`planner_tools.first_collision`, constant-velocity prediction).

## 5. Dataset (`training/data.npz`)

* **400 random episodes** (seeds 0–399), generated by `random_scenario()` in `training/collect.py` from `scenario_tools` only. The seed cycles through 4 scene types:
  * straight 2+2 road and S-curve road: slow and braking cars and trucks ahead, left-lane traffic, oncoming cars;
  * crosswalk road: the same traffic plus 1–3 pedestrians crossing at random times;
  * junction: uncontrolled, stop signs or signals; straight, left or right; crossing and oncoming cars.
* **Speed limits:** every scene has a posted limit, picked at random from typical US urban values: 25, 30, 35 or 40 mph on the straight and curved roads, 20, 25 or 30 mph at the crosswalk and the junction. The expert is told to drive at the limit (`desired_speed_mps = speed_limit_mps`), so the network learns its cruise speed from the limit alone.
* **Expert:** the baseline planner drives every episode. At every planning step (20 Hz) the recorder stores `encode(obs)` and the expert's trajectory converted to the 16 outputs.
* Episodes where the expert itself crashed or left the road are dropped: 25 of 400. That leaves **242,213 samples**. The expert's mean score on these random scenes was 79.8.
* Arrays: `X` (242213 × 141, float32), `Y` (242213 × 16, float32).

## 6. Training (`training/train.py`)

* Behaviour cloning: mean-squared error between the network's outputs and the expert's, both normalised. The mean and standard deviation are saved inside `model.pt`.
* Adam, learning rate 1e-3, batch size 256, 30 epochs, `torch.manual_seed(0)`, CPU.
* Took about 1 minute on a 20-core desktop CPU (collecting took about 4.5 minutes).

**To reproduce or retrain** (from the project folder; both steps overwrite the shipped files):

```bash
pip install -r training/requirements.txt
python training/collect.py 400        # -> training/data.npz          (about 5 min on 20 cores)
python training/train.py              # -> planners/learned_example/weights/model.pt   (about 1 min)
python evaluate.py --planner baseline learned_example
```

`collect.py` is deterministic. `train.py` can differ in the last digits between machines (multi-threaded floating point), so retrained weights score slightly differently.

## 7. Results (shipped weights)

| Scenario | learned_example | baseline |
|---|---|---|
| `lead_vehicle_brakes` | 44.1 (88 % progress, time limit) | 92.9 |
| `lane_change_overtake` | 37.8 (76 % progress, time limit) | 98.2 |
| `intersection_crossing_traffic` | 100.0 | 96.7 |
| `my_crosswalk` | 100.0 | 97.6 |
| **Total** | **281.9 / 400** | **385.4 / 400** |

No collisions, no road departures, no planner errors and no rule violations in any of the four. `plan()` takes about 1 ms. The two 100s come from driving at the speed limit (11.2 m/s), faster than the scenarios' desired speed. It loses on the two road scenarios because it is too cautious: in `lead_vehicle_brakes` it slows to about 4 m/s at the start although the lead car is 45 m ahead, and in `lane_change_overtake` it follows the truck at 5 m/s and never overtakes.

The planner reads `obs.speed_limit_mps`, never `obs.desired_speed_mps`: changing a scenario's desired speed does not change how it drives (only the score's ideal time).

## 8. What went wrong while building it (worth knowing)

1. **Exploding normalisation.** The first dataset contained only straight roads, so features like "signal state" never varied. Normalising by their standard deviation (≈ 0) multiplied them by about a million at the first traffic light, and the network output speeds of 180,000 m/s. Fix: `train.py` leaves features that never varied unscaled. The planner also checks that the output is plausible.
2. **Too little variety.** Trained only on straight roads, the network failed every junction and crosswalk. Fix: random scenes of every road type.
3. **Drifting.** When the network predicted (x, y) points relative to the car, it never learned to steer back after a small drift: the expert is always centred, so there were no examples of correcting. The car slowly left the road. Fix: predict offsets relative to the **lane centre**, so "go back to the centre" is the natural output.
4. **Impossible lane choices.** During lane changes the network sometimes asked for a lane that does not exist. Fix: clip offsets to lanes that exist and may be entered.
5. **A lower training loss is not a better driver.** Adding learning-rate decay lowered the training loss, but the planner then scored 147.5 instead of 281.9 and crashed at the intersection. Small errors add up when the network drives itself (it reaches states the expert never visited). Always judge a model with `evaluate.py`, never by its loss.

**Ideas to beat the baseline:** DAgger (drive with the network, label with the expert, retrain), more and harder random scenes, a better expert, predicting a stop distance instead of speeds, reinforcement-learning fine-tuning with `training/env.py`.
